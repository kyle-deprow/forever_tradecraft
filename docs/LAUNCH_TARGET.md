# Launch target

Crowley keeps one checked-in, strict target contract at
`src/crowley/data/game_target.json`. It is the verified beta target until a
future launch is explicitly measured and qualified; no launch-day build,
realm, route, or economy facts are inferred here. The contract supplies the
full client build, native build/interface, executable/window class,
product/flavor, locale, realm, faction/house, route provenance, and scan
cadence/cap/price-level settings.
It also records the verified installation `gameRoot` and `winePrefix` as
strict absolute, non-root paths; these machine paths are used by Python
staging/export orchestration and are intentionally not emitted to Lua.

The target is packaged with the Python wheel. Runtime consumers load it through
`crowley.core.game_target`; unknown fields, missing fields, booleans or floats
in integer positions, invalid House values, inconsistent houses, malformed
builds, unsupported cadence values, and multi-component product directories
fail closed. The catalog loader checks the target-bound catalog metadata.
The generator reads raw catalog JSON independently, binds its build metadata to
the selected target, and then renders the canonical catalog, packaged target,
addon target, TOC interfaces, and optional staged configs. Operational Python
qualification and default plan emitters consume that same packaged plan count;
historical payload fixtures remain wire-admission tests rather than launch
facts.

The client-data exporter currently supports only the target's `enUS` locale and
passes the target full build into its pinned offline exporter. A target edit
does not claim that a new locale, build, route, realm, or economy is available;
those require separately measured and reviewed inputs. Session and companion
loaders reject stale explicit target identity, flavor-root, and canonical-plan
values before startup.

The native region ID and realm are also target facts. The addon requires both
native values to match the selected target before auto-attributing a house; a
deliberate `/crowley set` override remains the explicit escape hatch for that
field. Native faction and neutral-zone detection remain live client facts.

Use the following commands from the repository root:

```text
uv run python tools/generate_launch_target.py --check
uv run python tools/generate_launch_target.py --write
uv run python tools/generate_launch_target.py --write --stage-config-dir /path/to/stage
```

`--check` never writes. `--write` updates only generated repository artifacts
and a requested staging directory; it does not modify live deployment config,
installed game files, Data.lua, SavedVariables, routes, or evidence. Review the
staged `session.toml` and `companion.toml` before any separately authorized
deployment. Staging rewrites the target wine prefix, companion flavor folder,
and the SavedVariables/Data.lua paths while preserving their account/addon
suffixes and unrelated settings. Destination preflight rejects checkout/live
config, installed Crowley config, current/selected game roots, Wine prefixes,
and symlink paths before generated bytes are written. The current beta route is accepted only with its exact measured
provenance and verified beta full build; changing the target rejects that
historical route until a new route is measured.

The scan cadence is deliberately a fixed 900-second policy because the current
wire contract admits only that cadence. A future target change must first add a
measured, compatible wire contract; changing this field in the target alone is
rejected. The beta sweep cap and all live launch qualification still require
fresh evidence after any target change.
