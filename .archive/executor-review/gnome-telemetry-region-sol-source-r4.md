## Must Fix

1. **The compiled producer's active-primary guard is permanently false.** `tools/gnome-telemetry-region/0001-typed-telemetry-area.patch:73` initializes `telemetry_capture_active` to `FALSE`, and the only other reference at `tools/gnome-telemetry-region/0001-typed-telemetry-area.patch:119-123` reads it; no path ever sets it. After the first telemetry process becomes the canonical local `GApplication`, an ordinary non-telemetry `gnome-screenshot` invocation can therefore pass the pre-parser, forward to that active primary, and enter its command-line handler instead of being rejected. This leaves the shared screenshot configuration and Shell path open to a second request while the typed capture is active, directly missing the R3 requirement to reject foreign command lines. The existing competing-owner fixture covers a second telemetry invocation rejected as remote; it does not cover an ordinary foreign invocation forwarded into an already-active telemetry primary. Set the flag immediately after the first local telemetry request completes its owner ACK, keep it set through the asynchronous capture, and clear it only at a defined terminal completion/failure boundary (or terminate the one-shot primary there). Add a compiled private-bus test that blocks the first real Shell capture, invokes a stock/non-telemetry command against the same canonical application, proves nonzero refusal with no second Shell call/output, then releases and completes the original request. Rebuild and freeze a new private binary because this correction changes the C producer.

2. **Ordinary daemon region captures still bypass the new Guardian observer ownership fence.** `src/crowley/session/daemon.py:1817-1832` routes the default region-enabled `capture_status`/`NativeMotionProvider` path to `DesktopDriver.capture_native_region_for_identity` without `observer_admission` or `observer_reaped`; `src/crowley/session/driver.py:2873-2878` then directly releases the child exec gate when those callbacks are absent. Only `capture_paused_region_sample` supplies the Guardian callbacks. During an unarmed native/bootstrap observation with no other Guardian-owned process, pause or stop can therefore see no active observer, skip the physical-release callback that advances the backend capture epoch, and allow this production producer to continue toward publication. This violates the integrated region contract's capture-revocation invariant even though the paused IPC path itself is fenced correctly. Route every production X11 telemetry-region capture through the owning driver's `guardian.observer_dispatch_admission`, retain registration until confirmed reap, and bind the applicable controller generation/state predicate at admission; keep callback-free invocation only as an explicit low-level offline fixture boundary if still needed. Extend `tests/test_session_native.py:328-506` with a blocked compiled default-daemon capture raced by pause/stop, asserting Guardian registration before Shell entry, epoch revocation, no final publication, confirmed reap/unregistration, and healthy retained lease/watchdog.
