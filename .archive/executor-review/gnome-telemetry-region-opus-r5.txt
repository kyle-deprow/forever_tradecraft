## Must-Fix

**1. The C foreign-command guard only covers forwarded command lines. GNOME's D-Bus activation and action calls get past it.**
- **Where:** `tools/gnome-telemetry-region/0001-typed-telemetry-area.patch:121-125` is the only guard (it handles the forwarded `CommandLine` case). At `:161-179` R5 adds parameters to the upstream `action_screen_shot` / `action_window_shot` handlers but no guard. The upstream `screenshot_application_activate` is also unguarded. I confirmed these against the pinned upstream source tarball.
- **What happens:** the telemetry producer is the registered `org.gnome.Screenshot` app while a capture is in flight. During that time, any of these D-Bus calls is dispatched on its main loop:
  - `org.freedesktop.Application.ActivateAction("screen-shot"|"window-shot")`
  - `org.gtk.Actions.Activate`
  - `Activate`
- **Trigger:** this machine's `org.gnome.Screenshot.desktop` has `DBusActivatable=true` and `Actions=screen-shot;window-shot`. So simply launching Screenshot, or one of its quick actions, from GNOME Shell reaches the producer. So does `gapplication action org.gnome.Screenshot screen-shot`. None of these start a new process, so the new flock never sees them, and they are not command lines, so the active flag doesn't either.
- **Impact:**
  - The action handlers rerun the shared option parsing, which sets `telemetry_region = FALSE`, and then start a second Shell screenshot with the flash on. The owner's completion proof is skipped and the user's screenshot ends up in our private stage file.
  - `Activate` sets `interactive = TRUE` and opens the dialog. The producer then doesn't exit and gets killed.
  - The Python side still refuses to publish anything. But the in-flight capture fails, and R5's central claim ("refused before a second Shell call, output, or shared-option reparse") doesn't hold for these routes.
- **Fix:** in a telemetry process (key on `telemetry_region_arg`, which is set before registration), refuse or ignore `activate` and every app action. Optionally refuse any foreign command line once the process's own invocation has been handled. Then add compiled cases that make the `gdbus` Activate / ActivateAction calls during the blocked Shell call. Each should assert: no extra entry in the area or stock logs, no output file, and the original capture still completes.
