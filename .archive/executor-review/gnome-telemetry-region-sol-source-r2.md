# Sol source review: GNOME telemetry region R2

Scope was limited to the frozen telemetry-region implementation and its named tests and build artifacts. I did not run tests, perform captures, operate the game, or inspect unrelated executor subsystems. The parent verification records 14 focused host tests and the compiled private-producer harness passing. Its namespace batch ended with 275 passes and 21 failures plus forced teardown; the failures were independently isolated to `os.execv` returning `EACCES` for executable memfds in that namespace, including unchanged protected-input cases. That result is an environment limitation, not evidence that this source regressed, but it also is not a broad-green or live-production result. No eight-sample paused diagnostic was run, and the frozen source does not yet contain the bounded runner required to conduct it.

## Must Fix

1. **The child treats one stream `read()` as one complete ACK record.** In `tools/gnome-telemetry-region/0001-typed-telemetry-area.patch:371-382`, the genuine producer polls a `SOCK_STREAM` socket once, calls `read()` once, and compares whatever bytes arrived with the complete ACK. A valid ACK sent by `driver.py:2852-2858` may be returned as a short read; stream sockets do not preserve write boundaries. The result is a false terminal producer failure before `ScreenshotArea`, with no hidden retry, which can abort the diagnostic or a formal native run. Read through the newline under the existing 15-second bound, handling `EINTR`, enforcing the 256-byte cap, and rejecting EOF, overlong records, or bytes after the one exact record. Add an actual compiled-producer test that sends the correct ACK in at least two writes; `offline_harness.py:337-342` currently sends it in one `sendall()` and cannot expose this bug.

2. **No test traverses the actual producer through the production parser and default daemon binding.** `tests/test_session_native.py:220-240` replaces `capture_native_region` with a `RecordingBackend` method that writes a prepared image. The region-enabled half at `tests/test_session_native.py:292-316` therefore reaches `SessionDaemon -> NativeMotionProvider -> capture_status -> DesktopDriver -> PixelDecoder`, but bypasses the sealed executable, admission gate, strict owner/start/completion protocol, and genuine GNOME producer. Conversely, `tools/gnome-telemetry-region/offline_harness.py:299-388` drives the genuine binary and exact pixels directly, stopping before `X11Backend`, `DesktopDriver`, `PixelDecoder`, `MotionFrame`, and the daemon binding. The synthetic ELF fixture in `tests/test_session_capture.py:109-246` proves the parent admission half but does not close that seam. This falls short of the plan's explicit non-substitution requirement at `PLAN-gnome-telemetry-region.md:221-253`, leaving the exact installed binary's sealed-memfd/GApplication behavior and record types unverified in the path the default provider uses. Extend the existing private D-Bus/Xvfb fixture to invoke the compiled producer through `X11Backend` and `DesktopDriver`, then decode it through an actual region-enabled `SessionDaemon.motion_provider`. Assert the resulting `MotionFrame`, live receipt, exact rectangle/pixels, and that `_capture_model()` on that same region-enabled daemon still uses stock full capture.

3. **The release-gated eight-sample diagnostic has no runnable implementation.** `tools/gnome-telemetry-region/offline_harness.py:615-633` exposes only `--self-test` and `--self-check`, and no other frozen owned file implements the plan's bounded paused diagnostic at `PLAN-gnome-telemetry-region.md:261-274`. As frozen, there is no reviewed command that predeclares at most eight one-second targets, uses the configured production `DesktopDriver` region method plus `PixelDecoder`, records every attempt/receipt/identity/boot/sequence/digest/retirement fact, and stops on the first hidden retry, `NO_CHANGE`, cadence, freshness, identity, or cleanup failure. Add that narrow diagnostic runner under the existing tool fence, keep it inert unless explicitly invoked after both reviews and parent release, and cover its pure scheduling/result validation offline. The live eight-sample execution remains a later operator step; this finding is about the missing reviewed runner, not the absence of live results.

## Should Fix

1. **The private parser accepts the forbidden short delay form `-d 0`.** The pre-parser rejects only `--delay` forms at `tools/gnome-telemetry-region/0001-typed-telemetry-area.patch:531-540`; the later configuration check at lines 205-215 rejects delay only when its parsed value is greater than zero. GNOME 41 defines `-d` as the delay option, so `-d 0` survives both checks in telemetry mode even though the adopted contract rejects the presence of any delay option. Reject all short conflict forms in the pre-parser (or carry explicit option-presence counts into the configuration check) and add `-d 0` to `_compiled_parser_checks()` in `offline_harness.py:471-559`. Production currently constructs a fixed argv without this option, so this is a strict producer-surface defect rather than a reachable daemon bypass.

2. **The source-controlled build recipe does not enforce its pinned container identity.** `tools/gnome-telemetry-region/build-private.sh:56-60` accepts any `GNOME_TELEMETRY_REGION_CONTAINER_DIGEST`, or records `null`, rather than requiring the digest documented at `README.md:35-43`. The frozen R2 binary has separate parent evidence showing the intended image was used, so this does not invalidate that binary. It does mean a later run of the reviewed recipe can emit a superficially valid manifest from an unpinned environment, contrary to the reproducibility requirement. Define the expected image digest in the script, require the supplied value to equal it, and fail before extraction/build when it is absent or different.

3. **Most new strict-protocol and publication failure branches have no region-specific regression test.** The focused tests cover successful output, pre-ACK revocation, and several `owner_ready` mismatches, but do not exercise malformed/out-of-interval `capture_started`, malformed/digest-mismatched `capture_complete`, wrong-size or non-PNG region output, post-capture identity drift, deadline expiry, or attempt-directory retirement. The similarly named tests later in `tests/test_session_capture.py` exercise the older stock screenshot path, not `capture_native_region`. Add focused producer variants for these cases and assert zero final publication, process/group removal, and attempt-directory retirement. This is especially useful around `driver.py:2859-2961`, where a future ordering or cleanup regression could otherwise pass the present 14-test region set.
