## Nits
1. **Outcome labels come from error text** (`daemon.py:343-351`).
   - A timed-out X11 query says "desktop command timed out" (`driver.py:1812`), so it is labelled `failed`, not `deadline`.
   - A stop after the producer is running shows up as a producer-exit error, labelled `failed`, not `cancelled`.
   - Fix: classify from the deadline or cancel state, or document that these two labels undercount.
2. **`status` doesn't mean the request succeeded** (`daemon.py:440`). It means all four identity lookups finished.
   - These failures all still report `complete`:
     - identity drift caught after `daemon_post` (`4236`);
     - config, admission or cleanup failures;
     - receipt-write failures.
   - Fix: document this or rename the field. The report's `response_ok` field does disambiguate.
3. **An interrupt can be swallowed** (`daemon.py:4274`). This `except BaseException` doesn't set `interrupted`.
   - So a KeyboardInterrupt or SystemExit during the final source check becomes an ordinary failure response instead of propagating.
   - That is inconsistent with `4259-4261`, and the base code used `except Exception` here.
   - Fix: set `interrupted` here too.
4. **The report drops two useful fields** (`sidecar:529-558`).
   - It omits `events_truncated`, so a truncated event list looks complete.
   - It omits the profile's own owner clocks. The return clock is taken just before the profile is written (`daemon:4410`).
   - With that clock, the report could separate receipt-writing time from profile-writing plus transport, which `owner_return_to_response_received_ns` (`sidecar:600`) currently lumps together.
