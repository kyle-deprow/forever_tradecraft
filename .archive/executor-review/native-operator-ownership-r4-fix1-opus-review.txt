## Must-Fix

**1. The new reservation expiry from bootstrap never reaches the cancellation actor** (`tools/native_calibration_operator.py:2525-2528`)
- At bootstrap, R5 resets `expiresMonotonic` to now + 3130 s (`daemon.py:1723-1726`). The helper accepts this at `running` (`:366`) but never calls `_arm_cancellation_actor`.
- The actor keeps the prepare-time expiry: now + min(reload deadline, 600 s), and the reload deadline defaults to 45 s. When that passes, the actor exits silently (`:1374-1376`).
- **Effect:** for most of the measure phase (release, click, hold, measure, resume, finalize, up to about 52 minutes), helper death leaves the consumed reservation with no one to cancel it. The helper never notices the actor is gone.
- **Fix:** after the bootstrap adoption, send an acknowledged `update()` before `_start_native_calibration` or any further input. Treat any update failure as fatal. The fix1 plan explicitly names this "new-expiry" boundary.

**2. Failure paths disarm the death-cancellation actor**
- `_cancel_active_reservation` sends the stop frame `S` *before* the helper's own cancel (`:2418`).
- The signal handler keeps raising until `_cleanup_started` is set in `finally` (`:2581`). So a second TERM/INT during the except-branch cancel IPC is swallowed by `except Exception` (`:2435`). The reservation stays admitted and no actor is left.
- In the recovered branch, a failed `_recover` never cancels the recovery reservation (`:2569-2577`).
- The `finally` block sends `S` unconditionally (`:2584`).
- A signal raised while `actor.close()` is running escapes the except block and replaces the first failure.
- **Fix:**
  - Send `S` only once the binding is confirmed terminal (finalized, recovered or cancelled).
  - Otherwise close the control pipe without `S`, so EOF makes the actor cancel the exact ID, and wait a bounded time for it.
  - Make the helper's own cancel run before the stop, and protect it from handler raises.

**3. The release and cancellation actors aren't independent of signals sent to the whole process group** (`:1182-1206`, `:1483-1501`)
- The emitter calls `setsid` (`:841`); the watchdog and actor don't. They share the helper's process group and controlling terminal. `_watchdog_entry` has no signal handling, so SIGINT becomes a KeyboardInterrupt and the process exits with code 1 without releasing.
- `release_now()` and `close()` count any exit as confirmed release, because `_bounded_process_join` ignores the exit code (`:903-913`, `:1270`, `:1300`).
- **Scenario:** Ctrl-C, a terminal hangup or `timeout(1)` during a button hold kills the watchdog. The helper's `release_now()` then "confirms" release, and `abort()` lets the emitter exit without `mouseup 1`. Button 1 stays held and nothing reports an error.
- **Fix:**
  - Spawn through a small wrapper in the helper that calls `os.setsid()` and then calls `_watchdog_entry` or `_cancellation_entry`.
  - Require `exitcode == 0` before treating release as confirmed.
  - Add a test that sends signals to the helper's whole process group (`killpg`).

**4. The owned `type` emitter is bounded more tightly than the action it runs** (`:1085`, `:847-855`, `:974`)
- In the vendored xdotool (`xdo.c:986+`), each character costs a 50 ms press plus an 80 ms release, so 130 ms per character.
- Every `/crowley agent …` command (19–23 characters) therefore takes 2.47–2.99 s. That exceeds both the emitter's own `subprocess.run(timeout=2.0)` and the owner's 2.0 s PRESSED read. Only `/reload` (0.91 s) fits.
- **Effect:** production typing always fails, and xdotool is killed mid-keystroke. A character key is held about 38% of the time, and `type` publishes `keys=set()` (`:1092`), so nothing releases it. The game chat is left half-typed with possibly a stuck, autorepeating key.
- This is unchanged since the original R4, so it isn't a fix1 regression. The tests can't see it because the recorder exits instantly and the measure-sequence test uses FakeInput.
- **Fix:** derive the bounds from the fixed command length plus margin, capped by the operation deadline. Publish the exact keysyms the fixed text can hold, or use per-character owned key emitters.

**5. Coverage the fix1 plan requires is missing**
- **Bounded exit with a failed release:** "normal interpreter exit with the failed-release actor retained" is only shown with `owner.kill()` SIGKILL (`tests/…:1136`). The other test calls `close()` inside the test process (`:1001-1075`). Neither runs `main` to return code 2, then SystemExit and atexit.
- **Production main:** the production-main test (`:1352-1465`) covers only a button hold and SIGKILL. It has no key hold, no handled TERM/HUP/INT, no repeated signals during real cleanup, and no emitter reap or watchdog exit assertion.
- **Repeated signals:** the repeated-signal test (`:1587-1609`) only sets `_cleanup_started` by hand and checks the handler.
- **Handoff boundaries:** there are no death tests at the bootstrap, new-expiry or recovery-generation/ID boundaries. The handoff tests (`:1526-1585`) involve no death.

## Should-Fix
- **File descriptors leak on readiness failure:**
  - The Watchdog except block (`:1226-1235`) never closes `_write`, `_ack_read` or the sealed release-spec fd.
  - `duplicate_release_spec` (`:1181`) runs outside the `try`, so a failure there leaks all six pipe fds.
  - The CancellationActor except block (`:1510-1522`) misses `_control_write`.
  - The plan requires these to be closed, and the readiness test (`:1612`) only checks that the process died.
- **A failing `release_now()` skips cleanup** (`:1069-1074`, `:1096-1101`, `:1134-1143`). It skips `emitter.abort()`, so emitter fds leak and processes go unjoined, and it replaces the original failure. Put the abort in `try/finally` and keep the first failure.
- **Unconfirmed release goes unrecorded** (`:2588-2594`). When the run already failed, a cleanup error such as "could not confirm release" is recorded neither in `_first_failure` nor in the receipt's `failureCode`. The operator never sees that an actor was retained. Add a receipt event for it.

## Nits

  - A missing `socket_path` silently skips arming the actor (`:2320-2322`).
  - The `getattr(..., "release_now")` checks exist only for test doubles.
- **Dead code:** `_new_emitter` has two identical branches (`:1043-1049`), and the `FixedInput(run=…)` parameter is unused.
- **Small leak:** `OwnedEmitter.start` leaks `_gate_read` and `_status_write` if `process.start()` raises.
- **Integration note:** a retained watchdog keeps fds 0–2 open. A caller that captures the helper's output will wait on pipe EOF until the release succeeds.
