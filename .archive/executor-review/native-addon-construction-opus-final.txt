## Should-Fix
1. **Finalize no longer rearms the scan schedule when the auction house is open** (`Agent.lua:648`, `:657`; `Scanner.lua:47-53`, `:67-71`).
   - **Cause:** R4 releases the native fence before committing the new lifecycle.
     - At `:648` the lifecycle is still `"constructed"`.
     - The release hook calls `Schedule("native_construction_release")`, and `nativeBlocked()` refuses it because the lifecycle is `"constructed"` and the load's decision is `"deferred"`.
     - `:657` then sets `"finalized"` without scheduling again.
     - R3 set `lifecycle = "finalized"` before releasing the fence, so R3 rearmed correctly.
   - **What it breaks:** Stage B R3's rule that native release rearms the schedule while the auction house remains open.
   - **Concrete case:**
     1. In the deferred load, fire `AUCTION_HOUSE_SHOW` with the canonical plan.
     2. Run release, Construct, hold, measure (100), resume, finalize.
     3. The schedule trace ends with `request` then `refusal native_construction_fence`. No `timer_create` follows, and the scanner stays idle until the AH is reopened or someone runs `/crowley scan`.
   - **Reachability and impact:**
     - The helper's fixed sequence can't hit this: the Agentless `/reload` resets `ns.ahOpen = false` (`Scanner.lua:227`), and nothing reopens the AH before Finalize. It only happens if someone opens the AH during the deferred load.
     - The cost is limited to losing automatic scheduling for the rest of that load. Safety, recovery and the Finalize proof are unaffected.
   - **Coverage claim is wrong:** the final closure lists "auction-house schedule rearm", but `test_addon.py:845-857` toggles the Scanner fence directly in an ordinary load and never goes through Finalize.
   - **Correction:**
     - After `lifecycle = "finalized"` at `:657`, call `ns.Scanner.SetNativeConstructionFence(false)` again. The setter is idempotent and reruns the release hook after the commit.
     - Don't instead move the lifecycle assignment ahead of the publication; a failed publication would then leave a live timer behind.
     - Test the real Finalize path with the AH open, expecting `timer_create` with source `native_construction_release`, and a publication-failure variant that creates no timer.
   - **Restore load:** `:790` has the same ordering but is harmless, because `ns.ahOpen` is always false at `ADDON_LOADED`.

  - A plain ordinary load and an in-flight restore are still refused (`:879-891`).
- **Post-Finalize recover arms the fence** (`:549-550`): the next real OnUpdate frame decodes with the armed, empty-reason projection (`:984-992`).
- **Ordinary startup matches base again** (`:752-757`): a transient failure keeps the surface and its periodic retry, and the next frame decodes strictly. A constructor allocation failure is still a loud restore-only refusal (`:746-751`).
- **Transactions are not weakened:** Construct (`:577-585`), the restore load (`:778-813`) and Finalize (`:648-655`) all still check their publications.
- **Restore load keeps the marker through both publications.** If the second fails, the code:
  - detaches OnUpdate, hides every texture and clears the frame bytes;
  - writes a valid `failed/1` marker with the `recovery:` token;

  The fault is injected at the real serializer on its second call, and the test then recovers through the slash command and a new load. Both publications run synchronously inside `ADDON_LOADED`, so no intermediate frame can be rendered or captured.
- **Finalize failure:** a fault at the Finalize publication rolls back the fence and lifecycle without touching the marker. The command prints `publication_error`, never "accepted", and recovery stays reachable (`:721-756`).
