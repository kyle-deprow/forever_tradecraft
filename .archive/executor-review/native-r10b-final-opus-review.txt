## Should-Fix

**1. The finalize-wins controller-mutex proof and the cancel-wins terminal recheck were never implemented.**

Sol's R9 Should-Fix 1 required these. So did the R10 plan (lines 41-46) and the final arbitration (lines 98-101: "both later terminal rechecks/controller-mutex proof"). They are still missing:

- **The test is unchanged.** `test_native_construction_composes_real_png_runner_and_finalize` has the same AST as in R9.
- **The finalize-wins barrier is still timing-based.** At `tests/test_session_native_regressions.py:7410-7426`, `cancel_attempted` is set before `dispatch`, and the only check is `not cancel_done.wait(0.2)`.
- **The cancel never reaches the controller mutex.** Public cancel calls `_native_construction_flush_expiry` first (`daemon.py:2801` → `1004`). That blocks on the construction lock, which the transaction holds, so the cancel never gets to the controller lock at `daemon.py:2802`. The test does not show what it claims.
- **The cancel-wins branch has no later recheck.** Lines 7433-7445 check only the initial response, with no later `native_construction_recheck`.
- **Nothing maps or defers it.** The R10 closure, the freeze and the parent verification all omit it, which goes against the plan's "Do not silently drop a required race proof".

**Fix (tests only; R9 Opus already confirmed the production code is correct):**
1. Use a forwarding hook that signals after the real `flush_expiry` returns.
2. Let the final transaction take both locks.
3. Use a thin forwarding facade on `controller.lock` (the plan allows this) to record a failed non-blocking acquire by the cancel thread, then delegate to the blocking acquire.
4. In both orders, call the public `native_construction_recheck` afterwards and assert the exact `finalized` or `cancelled` terminal (handshake state and `reservationState`).
5. Map it by exact test ID in the closure.
