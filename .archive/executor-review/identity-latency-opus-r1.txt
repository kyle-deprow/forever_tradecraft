## Must-Fix

   - `_socket_request(Path(args.socket), …)` calls `connection.connect()` with a `PosixPath`. On the project's Python 3.12.12 I checked that this raises `TypeError: a bytes-like object is required, not 'PosixPath'`.
   - `except (IdentityLatencyError, OSError)` doesn't catch `TypeError`, so the only live route dies before request 0.
   - It's also a hand-rolled client, but plan:79 requires the existing one. The hand-rolled version applies a relative 1.25 s timeout to each socket operation instead of an absolute deadline plus grace. It skips the `SHUT_WR`, EOF and trailing-data checks, and it doesn't validate the response schema.
   - **Fix:** call `crowley.session.cli._socket_request(..., response_deadline=deadline, failure_evidence_grace=0.25)`, as `offline_harness.py:1884-1896` does, and add a test for the live route.
2. **The negative coverage required by plan:161-172 is mostly missing** (`tests/test_session_native.py:147,1690`). The only additions are one reader/manifest test and assertions on the eight-sample success test. There are no tests for:
   - a forced artifact-write failure (causal failure unchanged, profile absent, token only);

## Should-Fix
3. **Request config hashes aren't checked against the manifest before sending** (`sidecar:509-529, 551-569`). `--config-*-sha256` are sent as given and only compared with the manifest afterwards. The owner only format-checks `config_file_sha256` (`daemon.py:4022-4031`). So up to three live captures can run under a config-file binding nobody reviewed. **Fix:** take the values from the manifest, or require equality before request 0.
4. **Output locations aren't preflighted** (`sidecar:517-535, 572-584`). `_write_private_json` uses `O_EXCL`, so a reused `raw_dir` raises an uncaught `FileExistsError` after request 0 has already been sent. That means fewer than three requests and no report. A bad `--output` is only discovered after all three captures. **Fix:** check that `raw_dir` is new and empty and that the output path is writable before the first request.
5. **The size bound contradicts the event cap** (`daemon.py:470`, `sidecar:16`). One event serializes to about 300–323 bytes, so the 64 KiB limit is hit at about 210 events, below the 256 cap. Truncated profiles — the slowest, most interesting samples — are exactly the ones that disappear behind the failure token. **Fix:** raise both bounds together, or size the cap to fit, and test a full 256-event round-trip.
6. **Profiling overhead is unreported and sits on the response path** (`daemon.py:465-485, 4379-4388`).
   - The profile write, including fsync, runs after `finish()` and before the IPC response is sent. `artifact_write` is recorded as a zero-length instant before serialization, so the write's cost is never captured.
   - The sidecar doesn't record when it sent each request or received the response.
   - So the added latency, which can push a response past deadline plus 0.25 s grace, is invisible; plan:184 requires overhead to be reported.
   - **Fix:** drop the fsync (the rename is already atomic and the file is diagnostic), and/or record the write's duration and the parent-side send/receive times.
7. **The report leaves out the CPU data** (`sidecar:429-438`). It includes only barriers (wall time only) and intervals. The events, which carry owner CPU and the source/seal/protocol/cleanup substeps, are dropped, and no aggregates are produced. That leaves out the input plan:199 says the next decision depends on. **Fix:** include the validated events, or at least per-barrier `identity_return` CPU plus per-name aggregates.
8. **Installing and resetting the sink isn't exception-safe** (`daemon.py:3972, 4388`).
   - The sink is set before the `try` and reset after the `finally`.
   - An exception that escapes skips the reset — for example from the unguarded cleanup snapshot at 4241 or `_model_call_snapshot` at 4005/4254.
   - The connection handler keeps reading requests on the same thread (`cli.py:440-466`), so later requests append to the stale collector. This is the cross-request contamination the intent forbids.
   - **Fix:** wrap the whole body in `try/finally` for the reset.
