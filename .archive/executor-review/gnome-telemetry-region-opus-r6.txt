**2. A late `gdbus` call can start the stock `gnome-screenshot` (non-blocking).**
- The RPCs are staged with fixed 50 ms sleeps (`:768-770`), and the gate is released at `:772-773` with no proof the calls were delivered. If a call (or its introspection) reaches the bus after the producer exits, the bus starts `/usr/bin/gnome-screenshot --gapplication-service`, because:
  - this host has `org.gnome.Screenshot.service`;
  - the fixture's `dbus-run-session` (`offline_harness.py:671`) uses the default session config, which includes the standard service directories;
  - the bus's activation environment is pytest's environment from before the fixture;
  - `gdbus call` auto-starts services by default.
- **Consequence:** in this tty environment (no `DISPLAY`) the stock service can't start, so the test fails under load without passing falsely. Run from a desktop terminal, the stock dialog or action would reach the real display and save a file to the real screenshot directory before the test fails.
- **Fix:** send the calls with auto-start disabled (for example `busctl --address=… --auto-start=no`), or run the fixture bus without service directories, so a late call fails with ServiceUnknown.
