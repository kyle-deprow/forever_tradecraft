**What I checked and found correct:**
- **Where the callback runs.** It's inside the `growth_bytes > limit_bytes` branch, after `result.verify()` (`calibration.py:1676-1695`). A failed final read or identity check raises before any measurement exists.
- **Causal error.** The callback runs in `try/except Exception: pass`, and the limit error is raised after that block exits. So `__cause__` and `__context__` are both `None` and the message is the unchanged exact string. The runner re-raises it as-is (`calibration.py:4836-4843`).
- **Production wiring.** The meter is built in only one production place, `_ensure_native_memory_meter` (`daemon.py:1006`), and that path always installs the callback. The runner takes `driver.native_memory_meter` (`calibration.py:4268`). Both the construction and updates completion sites (`:4647` and `:4733`) are covered.
- **Binding to the current owner.** The archive is written only if all of these hold:
  - the failure string and growth still show an over-limit rejection;
  - the measurement matches the meter's identity and `completion_matches` against the window currently completing;
  - with `controller.lock` held: the state is `NATIVE_CALIBRATION`, `driver.native_memory_meter is meter`, a fresh identity resolves, and the pinned `/proc` identity re-checks.
- **Locking.** The lock order is controller lock, then journal lock, which matches the existing controller paths. No code waits or joins while holding the controller lock, so there's no deadlock.
- **Receipt.** It is built from the record the journal returns. Its keys must be exactly the payload plus `archiveOrdinal`/`archivedAt`. `verify()` recomputes the outcome ID and digest and requires an ordinal above zero and `durable is True`. The meter checks the receipt a second time.
- **Idempotence.** The journal deduplicates on `outcomeId` (`journal.py:463-474`), and floats survive the JSON round trip exactly.
- **Privacy and scope.** Files are written mode 0600 with file and directory fsync. On failure only a fixed token is kept, and nothing reaches the handshake, status or evidence. Archive counters stay inside the journal; no code outside `journal.py` reads them. The limit, qualification and public schema are unchanged.
- **Cleanup.** The window is cleared in a `finally`. The meter is closed and unregistered in the existing `run_native_calibration` `finally`. A closed meter refuses archiving because `_verify_identity` fails.
- **Test value.** These are the first tests that exercise `_ensure_native_memory_meter` itself. Each over-limit test fails loudly if its guessed status-read count is wrong.
