The source-derived 514-identity-resolution minimum is correct: 103 observations each incur the provider check, the backend's before/after checks, and the runner check; the 99 update-boundary checks plus runner-entry, hold-boundary, and memory-meter checks bring the total to 514. ## Must-Fix

1. **Remove the compression-only branch and make the region producer the single implementation path.** `.archive/PLAN-gnome-telemetry-region.md:44-52`, `:167-170`, and `:235-257` still describe a compression comparison, a separate binary, and up to four additional full-screen captures before selecting region mode. That conflicts with the adopted arbitration and expands both source and live-capture scope without resolving the measured 0.357-second Shell cost. Delete the compression variant and three-way comparison. Build and review one source-controlled GNOME 41.0 no-flash `ScreenshotArea` producer; use the existing causal measurements and pixel-count comparison only as rationale, not as a second performance branch.

2. **Define the exact status/native consumer routing; the current text excludes the formal native path.** The plan says only “the native telemetry provider” selects region mode and explicitly leaves status, transition, calibration, and closeout on stock capture (`:227-233`). In the actual source, `NativeMotionProvider` is bound to `SessionDaemon.capture_status` at `src/crowley/session/daemon.py:302-313`; `capture_status` uses the generic full-screen crop at `:1881-1909`; native bootstrap directly uses `capture_client_crop_for_identity` at `:473-483`; and every `NativeCalibrationRunner` observation reaches `_capture_native_frame_with_capture` and its full-screen helper at `:975-1010`. Thus the proposed routing would not accelerate the default motion/status path or the 103 observations of the formal native run.

   Specify one default-off profile capability that selects the region producer for exactly: (a) native bootstrap's 256x256 absence/status artifact, (b) `_capture_native_frame_with_capture` and all native calibration/named-addon observations that use it, and (c) `capture_status`, including its motion, transition, command-buffer, and closeout callers. Keep `_capture_model`, `_capture_model_artifact`, route/viewport model captures, input calibration, and other full-scene/model consumers on the stock producer. Route those three strict-HUD call sites through the new typed identity-bound region method without changing their existing decoder, deadline, generation, boot, sequence, freshness, or retention behavior. Tests must traverse the actual default `SessionDaemon -> NativeMotionProvider -> capture_status` binding and the actual native measurement provider, while proving model/full-scene calls never select the region capability.

3. **Replace the impossible post-exit identity check with a concrete pinned-executable and live-child proof.** The proposed step 6 (`:212-214`) asks for PID/process-start/executable/PPID/PGID/owner verification after the child exits, when `/proc/<pid>` may already be gone. The configured path/hash checks at `:185-204` also leave a check-to-exec replacement window, and the current `_resolve_wrapped_executable` rejects a private absolute binary unless it already resolves through the installed PATH allowlist (`src/crowley/session/driver.py:251-261`).

   Define a dedicated region-executable capability rather than widening generic command resolution: open the absolute binary with no symlink following, verify the open file's regular-file/owner/mode/hash metadata, retain that exact file descriptor, and execute the retained object through the existing positive admission wrapper and process-group lifecycle. Seal the exact region argv, output path, rectangle, and a per-request nonce. The private fork must emit a nonce-bound self-owner/branch receipt over an inherited capability pipe after it is the non-remote registered GApplication and while the admitted PID is alive. At that point the parent can bind the receipt to the admitted PID and verify process start, executable object, PPID/PGID, and active-process-group membership before accepting the eventual exact `ScreenshotArea` result. Failure to become the primary genuine owner, a forwarded/remote invocation, missing/mismatched receipt, or process exit before live proof must fail closed. Reuse the existing capture lock, admission, cancellation, deadline, termination, and attempt-directory cleanup; do not add the old 0.3-second owner-monitor quiet drain to the runtime path.

4. **Treat the X11-to-Shell rectangle formula as a candidate until its coordinate basis is proved.** Lines `172-181` call `child_x + crop_x, child_y + crop_y` the only request, but Xwayland root geometry and GNOME Shell `ScreenshotArea` coordinates are not established as the same scaled coordinate space by a unit arithmetic test. Keep that exact formula and integer-only contract as the sole candidate, then make the first released region capture a basis gate: fresh identity, exact requested rectangle in the receipt, exact 256x256 PNG, and successful strict HUD decode at the configured live crop. A mismatch must stop the diagnostic. Do not add scale guesses, rounding, alternate offsets, tolerance, threshold changes, or fallback cropping. Retain the non-default-origin unit case to catch the old 80/48 assumption.

5. **Make the eight-sample gate runnable in the actual paused state and define its cadence measurement.** Lines `311-330` require the live diagnostic to use the native provider/public entrypoint, but `_native_measurement_provider` is a phase-specific calibration producer and cannot be honestly invoked while the daemon is paused merely to benchmark normal HUD frames. The same section requires every sample to meet 0.75..1.25 seconds and have “no skipped publication” without defining request spacing or how that stronger claim is proved.

   Keep the real public binding in integration tests. For the paused live diagnostic, call the configured production `DesktopDriver` region method with its real identity resolution and `PixelDecoder`; do not add a controller state, CLI bypass, or fake calibration phase. Predeclare at most eight one-second monotonic start targets, wait outside the measured path, and record each target, actual start, capture return, strict-decode end, and every underlying capture attempt. Require the complete identity-to-region-to-decode path to finish in under one second and the actual scheduled start/accepted-sample intervals to fall within 0.75..1.25 seconds. Require fresh strict frames with one boot and strictly increasing sequences, but remove the unsupported contiguous/no-skipped normal-frame claim. A capture error, `NO_CHANGE`, late/wrong output, or hidden provider retry must be recorded and stop this diagnostic; if an existing polling provider is exercised in tests, expose every attempt rather than reporting only its eventual success. The later formal run remains the only proof of the full construction/held/99-update/held-100/resume contract.
