## Should-Fix

**1. The worker-identity regression (Nit4) also passes on R8 code** (`tests/test_session_native_regressions.py:6625-6720`).
- The test asserts nothing between `old_thread.join` (6696) and `new_release.set()` (6698). After that, the new worker's `_finish_calibration` resets `state`/`error` and its own result write overwrites `result`.
- On R8, the old worker writes `"late old worker failure"` or its stale snapshot into the new record. The final assertions (state `complete`, `error == ""`, result kind `native`) still pass.
- The test also never reaches the "finally flips a new *starting* record to error" race, because it waits until the new record is `running`.
- **Fix:** assert the new record is unchanged (running, result None, error "") right after the old worker joins and before releasing the new one. Add a variant where the old worker's `finally` runs while the new record is still `starting`, with the new worker held before `_begin_calibration`.

**2. The NATIVE_CALIBRATION configured-producer execution gate is never run through the real method.** Final arbitration (Nit5) required this.
- **Untested code:** the NATIVE pre-check at `daemon.py:4566-4573`, and `admit_observer` (`4577-4598`) under NATIVE_CALIBRATION state.
- **Where the tests fall short:**
  - Both R9 linearization tests (5993, 6136) run in PAUSED.
  - The composed finalize test and `_configure_deadline_png_runner` replace `_capture_native_region_for_identity` (6862, 7156).
- **Why it matters:** this is the deferred-finalize path for the qualification producer, which is exactly where the strong "no revoked producer dispatch" claim applies.
- **Risk is low.** `admit_observer` doesn't depend on state, so the PAUSED proof covers the locking mechanism, and by inspection the NATIVE branch is correct. The requirement is still unproved.
- **Fix:** run `_r9_configure_png_capture` with a real deferred owner (prepare → bootstrap → `finalize_required`) and call the real gate with `expected_state=NATIVE_CALIBRATION`. Pause after the capability check and revoke via cancel or replay. Assert zero `process_calls` when revocation wins, and owner-clear-after-start when admission wins.

**3. An undocumented production fix to the public input gate has no regression** (`daemon.py:1215`, `1254-1257`).
- **What was broken in R8:** `start_calibration("input")` publishes a `starting` input record. The worker's `_begin_calibration("input")` then hit `current == "starting" and not (native and native)` and raised "a calibration operation is already starting". So IPC `input_calibrate` (`cli.py:177-195`) and the interaction-mode INPUT_CALIBRATION gate (`daemon.py:7768-7776`) errored immediately on every tick.
- **What R9 does:** it allows same-kind adoption and updates the record in place, which the Nit4 identity design needs.
- **The change looks correct.** Only the record's own worker can adopt it, because `start_calibration` refuses while a record is starting or running.
- **The gap:** the change is neither listed in the closure nor tested. The only test of the input start path is a refusal (5723).
- **Fix:** record it in the closure. Add a test that `start_calibration("input")` reaches `running` on its own record and publishes its result or error there, and that a cross-kind `starting` record still refuses.
