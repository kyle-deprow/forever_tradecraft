# Native motion prerequisites after the Opus r3 source repair

No input authority is granted by this document. C/D1 source corrections and
independent verification/review come first; the sole operator waits for root.

1. Align the owned GTK helper to production typed schemas/expected_argv, then
   prove private-tool emission/echo, timings and both cancellation boundaries
   under the global lease. This is not D1, human or game-motion acceptance.
2. Recover the sole existing client through normal login if still disconnected,
   leave Arthur stationary/AHclosed, and obtain bounded read-only native API
   diagnostics before changing the wire or sending movement/camera input.
   Verify the exact C_CVar.GetCVarBool("autointeract") accessor and distinguish
   false from nil/error; capture all four GetUnitSpeed returns, actual frame
   timing, and supported ground-mode predicates. No inferred config-file proof.
3. Only after those facts, scope a strict native capability/wire change with
   exact producer/decoder/fixture ownership. Missing/unknown/changed capabilities
   must block camera or invalidate calibration, never select another accessor.
   Preserve CRS1 capacity, native budgets, protected actions and historical data.
4. Measure actual capture/identity/model latency on the installed path. Remove
   redundant work only with maintained pre/post capture identity proof. Do not
   relax evidence ages or deadlines to hide infeasible timing.
5. Qualify per-role displacement/direction and uncertainty within the existing
   shared two-unit ledger. A proposed staged CLI with two-unit-per-role allowance
   changes that contract and needs an explicit reviewed plan amendment; it is
   not an implicit consequence of staging. Longer repeated probes that cannot
   fit the ledger do not constitute a working calibration design.
6. Prove the actual camera drag response only with Click-to-Move disabled and
   fresh clear viewport/position evidence; absence of yaw is a failure, not proof
   of a safe threshold. Establish a supported minimum from actual evidence.

These are source artifacts in Gethe's community-hosted mirror, not an official
Blizzard service or proof of this installed70425 client. Pin/compare the relevant
source snapshot before implementing assumptions. A native runSpeed ceiling is
only a candidate until units, mode, stability and observed travel are verified;
it cannot replace independent role measurements.

The previous staged-calibration proposal is therefore not approved for source
implementation yet. Keep its useful process-local lifetime and explicit role
requirements; collect the missing native facts before selecting the final model.
